# Demo Gate Lessons

These are durable operating lessons for agents preparing a recorded Phalanx Duel demo.

## Stable landing checklist

The demo is not considered green until all of these are true:

- Host-native Postgres is running and project commands select `phalanxduel_development` through `bin/maint/with-dev-postgres.sh` or `bin/maint/with-tooling-postgres.sh`.
- No command inherits the ambient `postgresql:///my` database, and local app work does not start Docker or Colima.
- `pnpm verify:quick` passes.
- `pnpm qa:playthrough:verify` passes with 12/12 scenarios.
- `bin/phx-healthcheck localhost:3001 --observability` reports app, database,
  OTel, OpenObserve, and Jaeger as healthy.
- `pnpm qa:visual:run` passes with 3/3 scenarios.
- The worktree is clean, `main` is pushed, and the final push-triggered Pipeline and Code Quality runs are green. In-progress CI is not green.

## Visual baseline discipline

Playwright baselines are platform-specific. Never copy a macOS/Darwin PNG into a Linux baseline. Use the manual `refresh_visual_snapshots=true` workflow input, review the uploaded Linux artifact, and commit the artifact generated by the Linux Playwright environment. Stabilize random visible identities in visual tests before refreshing snapshots.

## Automated UI and gallery capture

When capturing screenshot galleries or automated video footage via Playwright, modal dialogs (`WelcomeDialog`, `OnboardingBriefing`) will intercept pointer events unless explicitly dismissed. Scripted harnesses (such as `bin/qa/capture-gallery.ts` and `bin/qa/capture-design-baseline.ts`) must pre-populate `localStorage` via `context.addInitScript()`:

```ts
localStorage.setItem('phx_welcome_v1_seen', '1');
localStorage.setItem('phx_onboarding_deploy_seen', '1');
localStorage.setItem('phx_onboarding_combat_seen', '1');
localStorage.setItem('phx_onboarding_spectator_seen', '1');
localStorage.setItem('phx:helpOpen', 'false');
```

## Presentation LAN topology

To demo Phalanx Duel live across phones, tablets, or audience devices:
- DNS maps `*.lan.phalanxduel.com` to the host workstation's LAN IP (`<HOST_LAN_IP>`).
- Scoping to the `lan` subdomain ensures live production (`play.phalanxduel.com` on Fly.io) is never shadowed.
- The project Nginx vhost (`nginx/phalanxduel.localhost.conf`) terminates TLS using `zdots-local` certificates and proxies WebSocket upgrades to Fastify.
- Vite's `server.allowedHosts` must allow `.lan.phalanxduel.com`.

## Narrated video generation pipeline

The demo video assets are generated directly from code and markdown:
- `pnpm docs:demo:record`: Runs a headless browser match to record 30 FPS raw WebM footage and phase timestamps (`scripts/video/build/demo-raw.webm`, `footage.json`).
- `pnpm docs:demo:build`: Synthesizes voiceover from `scripts/video/demo-narration.md`, renders title cards, and produces the finalized video assets (`output/video/phalanx-duel-demo.mp4`, `.webm`, `.vtt`).

## Infrastructure boundary

Phalanx Duel's project DB isolation is independent from zdots' `my` database. If `zdots-ctx add-lesson` fails because zdots cannot connect to its ambient socket database, do not bypass the guard or redirect Phalanx commands. Record the failure in the handoff and continue with repo-local agent documentation; repair zdots infrastructure separately.
