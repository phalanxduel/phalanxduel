The purpose of the system is what it does.

Phalanx Duel is a coordination system disguised as a tactical card game: it turns human intent into authoritative state, preserves the causal trail, and returns a legible experience to players, spectators, and operators.

Its purpose is coordination under pressure. A player chooses. The line resolves. The system preserves the proof. Another person can watch the same truth live or walk through it later.

One interaction, across the strata

1 · Experience
A visitor arrives, signs in, joins, plays, watches, or rewatches.
2 · Session and edge
session.id, traceparent, and viewer/player intent cross the browser boundary.
3 · Authority
The server validates the action and the deterministic engine resolves the next state.
4 · Evidence
match.id, transaction sequence, action log, state hash, and redacted projection preserve what happened.
5 · Understanding
PVL maps the journey into traces, logs, metrics, spectator views, replay steps, and operator reports.

What the system does for each person

Player

Provides a fair, server-authoritative match with recovery, replay integrity, and a readable tactical line.

Visitor

Provides a low-friction public lobby, rankings, profiles, live matches, and a path into play without operator knowledge.

Spectator

Provides a safe observer projection that follows the live match without leaking private state or becoming a second player.

Operator

Provides a causal map from scenario runner to browser, service, engine, persistence, telemetry, and evidence.

PVL's test of truth

If a scenario says a flow exists but no trace, replay, or query evidence confirms it, PVL labels it unknown. If the run confirms it, the edge becomes observed. The diagram is useful because it makes both the system's behavior and its evidence gaps visible.
